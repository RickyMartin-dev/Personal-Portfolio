How Project Starter works.

A starter kit that gives any coding agent the same rules, the same commands, and a memory that lives in Git. No app, no server: just files, scripts, and checks.

The system at a glance

One set of instructions, one command line tool, and three things it looks after.

A task, start to finish

Every agent follows the same five steps. The commands do the bookkeeping so nothing important lives only in chat.

  1. Start

    ./scripts/project start loads context, installs Git hooks, and checks the repository is healthy.

  2. Plan

    ./scripts/project plan creates a short plan in docs/plans/active/ for anything bigger than a quick fix.

  3. Build

    The agent makes small changes, guided by AGENTS.md and the prompts in prompts/.

  4. Check

    ./scripts/project check runs every guardrail: files, secrets, workflows, memory, design.

  5. Finish

    ./scripts/project finish re-runs the checks, saves a snapshot, and writes a handoff for the next session.

What runs the checks, and when

Checks run automatically at the moments that matter. All of them are local scripts, so they work offline.

WhenWhat runsWhy
Checkout or mergeproject startRefresh local context for the new state of the branch.
Every commitproject checkBlock missing files, leaked secrets, and broken contracts.
Every pushproject release-checkRun the full gate, including whitespace in new files.
Pull requests and mainGitHub Actions: quality, securityRepeat the same checks on a clean machine.
WeeklyGitHub Actions: upgrade reviewPrint upgrade suggestions for a person to review.

Where the project remembers things

Memory is plain Markdown in Git, so any agent or person can read it, review it, and undo it.

Compaction

Snapshots of branch, commit, decisions, risks, and the next action, saved in docs/compactions/ before context runs out.

Research

Dated comparisons with sources in docs/research/. Outside ideas are input, never rules.

Upgrades

suggest-upgrades flags placeholders, missing project records, and missing specialist briefs. A person decides.

Specialists

Role cards in agents/ that spell out a helper's job and limits. They are reviewed before any agent uses them.

State

The current task, next task, risks, and handoff in docs/state/. Advisory until reviewed.

Decisions

One short file per lasting choice in docs/decisions/, with the options and the reason.

How design work is handled

The Impeccable skill is installed for all three agents. It reads two files and checks UI edits as they happen.

PRODUCT.md

Who the project is for and what it must feel like.

DESIGN.md

Colors, type, spacing, and components. Values live in .lavish/theme.css.

Design hook

After every UI edit, a detector reports layout and contrast problems for the agent to fix.

Trust model: files, web pages, and tool output are treated as untrusted input. Memory, research, and specialist cards never gain authority without a person's review.

Source of truth: AGENTS.md, docs/operating-system.md, .agentic/manifest.json, and scripts/. This page explains them; it does not replace them.
