A develop push builds both halves and checks the deployed model.

Pull requests run quality checks without AWS credentials. A push or merge to develop uses short-lived GitHub OIDC credentials for the AWS deploy, then publishes only the static artifact.

  1. Pull requests target develop

    Project Starter release checks, mocked backend tests, browser tests, secret scanning, and Terraform format/validation run without AWS access.

  2. Deploy the backend first

    The workflow builds a commit-tagged Lambda container, applies Terraform through branch-scoped OIDC, and makes one real chat request against the deployed endpoint.

  3. Publish the UI last

    The frontend build injects the public API URL and optional Web3Forms contact key. GitHub Pages receives frontend/dist/, not the backend, infrastructure source, docs, tests, or agent tooling.

Local and deployed inference share one model profile.

The same backend code and model setting make integration behavior comparable. Generated wording can still differ between calls because model inference is nondeterministic.

Local

./scripts/setup-local.sh creates the ignored backend/.env template and installs dependencies. ./scripts/dev.sh serves the website at port 8000 and FastAPI at port 8001. Use an AWS profile or local Bedrock bearer token; set BEDROCK_MODEL_ID to the Terraform model value.

Deployed

The Lambda execution role authorizes Bedrock. The API endpoint is public routing information in the website bundle; no AI token or browser API key is published. The smoke test calls the same configured model after each successful deployment.

Consistency boundary: local and deployed use us.anthropic.claude-haiku-5-5 by default, but matching model/profile settings do not guarantee byte-for-byte identical answers. Mocked tests make no paid inference calls; each successful deploy smoke test and each local live request does.

Four owner actions unlock the first deploy.

The repository contains the workflow and infrastructure code. These settings require access to the GitHub repository and AWS account.

  1. Prepare GitHub

    Create and protect develop, require checks for pull requests into it, and set Pages to publish with GitHub Actions. Keep direct pushes to main blocked while its legacy Pages workflow remains in remote history.

  2. Bootstrap AWS once

    Use the intended AWS CLI profile to review and apply backend/infra/bootstrap/. It provisions the encrypted Terraform state bucket and GitHub OIDC role restricted to this repository's develop branch.

  3. Set repository configuration

    Add variables AWS_REGION, TF_STATE_BUCKET, and AWS_ROLE_ARN. Add WEB3FORMS_KEY as a GitHub secret if the existing contact form should submit.

  4. Deploy and verify

    Merge the reviewed change into develop. Confirm the API health route, a real chat response through the published site, and metadata-only CloudWatch logs before planning old endpoint retirement.

Current cutoff: no push, live inference, bootstrap/apply, or AWS resource change has occurred. A push to develop starts the configured deployment; the old website chatbot endpoint remains in service until the new one passes its live check.

Idle infrastructure is small; inference and safety checks scale with use.

Cost shape

No VPC/NAT, provisioned Lambda, database, trace service, or always-on app server. Retained ECR images, the small Terraform state bucket, and log bytes can incur idle storage charges. Model and Guardrails calls are the main usage costs.

Signals included

CloudWatch receives API/Lambda metrics and structured request metadata: request ID, status, latency, token counts, and outcome. Prompts, replies, and conversation history are not logged.

Limits to understand

API throttling is best-effort rate control, not a monthly spend cap. The historical account baseline was about $1.08/month before this stack; the cost doc gives usage estimates and exclusions.

For exact pricing assumptions, resource cleanup candidates, and CloudWatch queries, use docs/deployment-and-costs.md, docs/legacy-chatbot-cutover.md, and backend/infra/terraform/README.md. The AWS inventory is a point-in-time record and must be refreshed before any deletion.
